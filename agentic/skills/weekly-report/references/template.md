# 周报模板与示例

## 输出格式说明

周报内容填入团队飞书周报表格，每行对应一个需求/事项，只需填两列：

- **重点项目**：项目名 + 项目级 context（整体进展、关键指标、风险）
- **任务描述**：`（进度%）` + PRD/需求链接 + 产出/参考链接（如有）+ What/Why/When/How

---

## 标准模板

```
【重点项目列】
[项目名]
[项目级 context：本周整体进展、关键指标变化、阻塞点或下周关键节点。如无则只填项目名。]

【任务描述列】
（进度%）
- PRD链接：[可点击的 PRD/需求链接]；无链接时填：PRD链接：未提供
- 产出/参考链接：[任务内 wiki/docs/Apifox/看板/代码仓库等链接及用途；无则省略]
- What：[本质上做了什么能力？解决了什么核心问题？]
- Why：[为什么要做这件事？业务背景或技术驱动因素？]
- When：[关键里程碑 / 完成时间 / 当前进展节点]
- How：[具体的技术方案或操作方法]
```

同一项目下多个需求：**重点项目列合并（rowspan）**，任务描述列每个需求单独一行。

## Git 信息来源

设置 `WORK_REPO_PATH` 时，先扫描 `aaas` 下仓库，再扫描根目录其他直接子目录仓库：

```bash
python3 scripts/fetch_git_work.py
python3 scripts/fetch_git_work.py --repo-root /path/to/work --week-start 2026-06-16 --max-files 200
```

处理 JSON 输出时关注：

- `week`、`repo_root`、`scan_order` / `scanned_repositories`：扫描范围和顺序。
- `repositories[].commits`：按每个仓库生效 `user.name` / `user.email` 与 commit author 精确匹配的提交；不按 committer 匹配。
- `repositories[].modified_files`：本周 tracked/untracked non-ignored 文件 mtime，仅作为工作线索，不直接证明成果。
- `warnings`：身份缺失或单仓库错误；不因单个仓库失败中断整体处理。

将 Git 证据与用户笔记、飞书需求数据合并核对。不能仅凭提交标题或文件修改时间臆造工作背景、成果或 PRD 链接；无法确认时询问用户。Git 扫描只读，不执行 fetch/pull/checkout，也不直接写入用户工作记录。无 `WORK_REPO_PATH` 时提示设置环境变量或使用 `--repo-root`。

Git 证据核查 SOP：先阅读本人 commit message，判断工作意图；message 不清楚或不足以说明 What/Why/How/结果时，检查该 commit 的 `git show` / `git diff`，必要时阅读变更涉及的相关代码和配置，确认实际行为。未提交修改只有 mtime 线索时，同样检查 `git diff` 和相关代码，但 mtime 只能作为时间线索，不得当作成果。只有上述证据仍无法确认背景、目标、结果或进度时才询问用户；已有充分证据时不要重复检查。输出任务描述时保留 PRD 链接，缺失时标注 `PRD链接：未提供`，不得从 Git 信息编造链接。

## 本地工作记录更新（可选）

当使用本 skill 的 `workingdir` 是个人工作记录目录时，先询问：

> 当前 workingdir 是个人工作记录目录，是否要把本周工作记录追加到本地？只有你明确确认后才会写入；拒绝或不确认则只输出周报。

用户明确确认后，读取该目录的 `AGENTS.md` 和目标年份文件（例如 `2026.md`），按年份文件现有 Markdown 分类、缩进、链接格式追加。以周一至周五日期范围作为日期型二级标题：已有本周日期标题则在该标题后、下一个日期范围周标题前追加，没有则在年份文件末尾新增分组；不要把项目标题等其他二级标题误判为周标题；不得覆盖或重写已有内容。`workingdir` 不是个人记录目录或用户拒绝时，不写本地文件。

追加内容示意（日期格式、分类和缩进以目标年份文件为准）：

```
## [周一日期] - [周五日期]
### [现有分类]
- [本次工作内容]（PRD链接：[可点击链接]）
- [无链接事项]（PRD链接：未提供）
```

仅追加本次工作内容；每个需求/事项的任务描述段落必须保留 PRD 链接或 `PRD链接：未提供`。写入前必须获得本次明确确认；若 `AGENTS.md`、目标年份文件或现有格式无法读取/判断，停止写入并询问，不自行创建或覆盖文件。

## 常见问题

**Q: 进度怎么填？**
已完成填 `（100%）`，进行中填具体比例如 `（80%）`，已上线填 `（已上线）`。

**Q: 项目级 context 从哪里来？**
需要询问用户。飞书任务 API 能拿到单条需求的描述，但项目整体状况（指标变化、阻塞、团队情况）只有用户知道。

**Q: 多个小事项（排查、配置）要合并吗？**
性质相近的可以合并进一个任务描述行，在 How 里列举具体问题。

**Q: 用户只有简短的任务名，3W2H 信息不全怎么办？**
优先询问 Why（最重要）和 When（进展节点）。不要凭空编造 How 的技术细节。

## 重点项目进展更新（风控2026重点事项表）

基于同一份输入，额外生成每个 AI 项目行的「关键进展」列更新。

### 格式

```
MM/DD 进度：
- [关键结果/当前状态]
- [当前阻塞（如有）]
- [接下来]
```

### 示例

```
【[项目A 名称]】
MM/DD 进度：
- [关键结果或当前状态，如：完成方案设计，已开始开发。]
- [当前阻塞（如有），如：依赖方尚未回复，推进受阻。]
- [接下来，如：下周完成联调，预计 MM/DD 上线。]

【[项目B 名称]】
MM/DD 进度：
- [关键结果，如：功能已上线，核心指标从 X 改善至 Y。]
- [接下来，如：持续观察数据，收集用户反馈。]

【[项目C 名称]】
MM/DD 进度：
- [当前状态，如：仍在产品验收中。]
```
